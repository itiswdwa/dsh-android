# dsh-android 1.1.4

## 这一版修了什么

- **修好了「升级了但界面还是老的」**：设置页里那几张卡片（检查更新、热更新包）在有些设备上不出现。
  原因是插件更新多绕了一环 —— 应用把插件写进 rootfs，再由沙箱里的启动脚本复制到 harness 读取的
  profile 目录；中间任何一步没发生，harness 就还在加载旧插件。现在**应用直接写 profile 目录**
  （同一个文件系统，不经过沙箱），少了一环就少一处能断。
- **设置页顶部常显版本号**：`应用 1.1.4 · 热包 7ca778d0 · 内置/已导入`。
  以前一台设备跑的是哪一版完全看不出来 —— 是"功能没写"还是"装了旧版"，只能靠猜。
  现在一眼就有答案，排查问题时直接把这一行发出来即可。

## 如果你之前在平板上装过

平板上那版应该是 1.1.3 之前的构建，所以看不到「检查更新」和「热更新包」两张卡片。装这一版即可。
装完打开 设置 → 安卓沙箱，顶部应该显示 `应用 1.1.4 · 热包 7ca778d0 · 内置`。

## 更新方式

- **热更新**（几十 KB）：设置 → 安卓沙箱 → 检查更新 → 一键应用。插件、技能、提示词、沙箱脚本走这条。
- **重要更新**（这个 APK）：界面、图标、桥的接口走这条。覆盖安装，会话/密钥/挂载/设置都保留。

拿到 `dsh-hot.zip` 也可以离线导入：放进手机 `Download` 目录，重开应用即可。

## 已知限制

- arm64 的 Android 8.0+ 设备。
- 「操作手机本身」（截图、开关应用、改设置）需要自行安装并授权 [Shizuku](https://shizuku.rikka.app/)，
  设置页那一栏会显示当前状态。
- 手机开着 fake-IP 模式的代理时，harness 的 `web_fetch` 会按设计拒绝公网域名，让助手改用
  `bash` + `node fetch`。

完整说明见 [README](https://github.com/itiswdwa/dsh-android#readme)。
