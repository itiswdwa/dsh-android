# dsh-android 1.1.5

## 这一版改了什么

**「安卓沙箱」设置页重画了一遍，和 harness 原生的设置页长成同一个样子。**

以前这一页是插件自己画的一套：灰底圆角卡片、蓝色按钮、自定字号，和旁边的「通用设置」「模型」
摆在一起像是两个应用拼起来的。现在它用的是 harness 自己的那套东西：

- **控件全部来自原生组件库**（`@deepseek-ai/dsh-client-ui-primitives`）——按钮、开关、状态点、
  标签都是 harness 自己那些，所以 hover、按下、焦点环、禁用态、无障碍角色跟原生完全一致，
  不再是"看起来有点像"。
- **颜色只走主题令牌**（`--dsw-*`），一个写死的颜色都没有，所以深色模式、以后换主题都不用改这里。
- **排版用原生设置页的形状**：18px/600 标题 + 13px 灰色说明，字段之间是 0.5px 发丝线，
  分组用 `settings-card` 那层描边卡片 —— 和「通用设置」里"权限/语言/字号大小"那几行是一个模子。
- 顺带把几处一直写死中文的地方（挂载的「启用/停用」、日志的「（无输出）」、发行版的「内置」）
  收进了语言表。

同一页在深浅两种主题下的样子：

| 改动前 | 改动后（浅色） | 改动后（深色） |
|---|---|---|
| 灰卡片 + 蓝色按钮 | 原生卡片 + 原生按钮 | 同一套令牌自动跟随 |

功能一个没少：服务启停、发行版切换与启动命令、热更新检查与应用、导出到手机、挂载（含"为什么这个
挂载看不到东西"的提示）、Shizuku 状态与测试命令、端口/Key/三个开关、日志。

## 顺手修的两处

- **构建脚本不再写死源码路径**：`build_apk.sh` / `assemble_payload.sh` / `sync_repo.sh` 现在按脚本
  自己所在的位置定位源码树（仍可用 `DSH_SRC_DIR` / `DSH_REPO_DIR` 覆盖）。别人 clone 下来放在哪都能编。
- 新增 `scripts/extract_css.py`：把 harness 客户端 bundle 里内嵌的 CSS 模块导出来。这次对齐原生
  样式就是靠它读的原始声明，而不是照着截图猜。

## 更新方式

- **热更新**（几十 KB）：设置 → 安卓沙箱 → 检查更新 → 一键应用。这一版的界面改动走这条就够。
- **重要更新**（这个 APK）：新装设备用。覆盖安装，会话/密钥/挂载/设置都保留。

拿到 `dsh-hot.zip` 也可以离线导入：放进手机 `Download` 目录，重开应用即可。

装完打开 设置 → 安卓沙箱，顶部应该显示 `应用 1.1.5 · 热包 <新哈希> · 内置`。

## 已知限制

- arm64 的 Android 8.0+ 设备。
- 「操作手机本身」（截图、开关应用、改设置）需要自行安装并授权 [Shizuku](https://shizuku.rikka.app/)，
  设置页那一栏会显示当前状态。
- 手机开着 fake-IP 模式的代理时，harness 的 `web_fetch` 会按设计拒绝公网域名，让助手改用
  `bash` + `node fetch`。

完整说明见 [README](https://github.com/itiswdwa/dsh-android#readme)。
